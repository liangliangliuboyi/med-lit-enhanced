## 三、"再检查一遍"发现的新问题（第二批，待你提个性化意见）

以下是这轮改造过程中新发现、或原设计里还留着的口子。**按我判断的优先级排序。**

### 高优先级

| # | 问题 | 说明 | 建议 |
|---|---|---|---|
| **N1** | **Europe PMC 是比 bioRxiv API 更好的预印本来源** | bioRxiv 官方 API **不支持关键词检索**，只能按时间倒序拉全部再本地过滤，召回率低。**Europe PMC** 收录 bioRxiv/medRxiv 预印本 + 专利 + 更多期刊，且有真正的关键词检索 API | 加 `--europepmc` 选项，用 Europe PMC 作为预印本与补充语料的主来源，bioRxiv API 降级为备选 |
| **N2** | **`querytranslation` 没被利用** | PubMed 在 esearch 里会返回它**自己怎么理解你的检索式**（自动 MeSH 映射、拆词等）。这是发现"检索式被误解"的最好线索，现在只躺在日志里 | 把 `querytranslation` 提到 `02_plan.json` 与日志显眼处；命中异常少时提示用户对照 |
| **N3** | **PubMed 的 MeSH 树没有充分利用** | 支持 `[MeSH:explode]`（含下位词）与 `[MeSH:noexp]`（仅本身）。planner 现在只会写基础 MeSH 词 | 在 planner 提示词里教会它用 explode（糖尿病要包含 2 型/妊娠型/继发等），并对关键概念优先用 explode |
| **N4** | **答案的结构完整性没有程序侧校验** | writer 承诺输出七段（含"适用边界"），但没人检查它是否真的给了、每段是否都有 PMID | 加一道后置校验：检查七个标题是否齐全、每段是否至少有一个 PMID；不合格时自动让 writer 重写一次 |
| **N5** | **不能横向对比两个干预** | "司美格鲁肽 vs 替尔泊肽哪个证据更强"是最常见的需求之一，现在只能跑两次人工对比 | 加 `--compare "干预A" "干预B"`：同一检索式跑两组证据，输出对照表与各自的 GRADE |

### 中优先级

| # | 问题 | 建议 |
|---|---|---|
| **N6** | **语种没有限制** | PubMed 支持 `AND english[la]`。不加会捞进大量非英文文献，稀释精读名额 | 默认加语种过滤（`--langs english` 可调） |
| **N7** | **`--cq` 必须显式指定，但 planner 已经有 PICO** | planner 输出的 PICO 足以推断该用 therapy/diagnosis/prognosis 哪个过滤器 | 让 planner 输出 `suggested_cq`，**仅作建议展示给用户**，不自动 AND（保持"不替用户做决定"的原则） |
| **N8** | **没有检索结果缓存** | 同一课题反复检索会重复打 API，也重复付费 | 对 `esearch` 结果做本地缓存（按检索式哈希），同一检索式直接复用 |
| **N9** | **成本估算只有一个全局单价** | 不同模型价格差很多 | 按模型分档计价，`models` 段加每角色的单价 |
| **N10** | **`exclude_pub_types` 不完整** | 缺 `Preprint`、`Retracted Publication`（它本身是噪声）等 | 补全噪声类型清单 |
| **N11** | **快速模式把链接扩展全关了** | `--quick` 合理地省时间，但检索式修订（质量闸门）也被连带关掉了 | 快速模式保留检索式修订，只关链接扩展与滚雪球 |

### 低优先级

| # | 问题 | 建议 |
|---|---|---|
| N12 | 答案里没有"检索到什么 / 没检索到什么"的透明声明 | 加一段"本次检索覆盖的问题要素 / 未覆盖的要素" |
| N13 | docx 导出没处理表格（转成 tab 分隔的段落） | 若要做正式交付物，需支持真表格 |
| N14 | 只校验 PMID 存在性，不校验内容对应 | 与 B5 同源，成本高 |
| N15 | 没有"最近 N 次运行"的横向对比视图 | 可从 `runs/_index.md` 升级成可排序的表 |

### 三个子代理实测报出的问题（已全部处理）

| # | 来源 | 问题 | 状态 |
|---|---|---|---|
| P1 | stats-dev | **Europe PMC 的 `source=PPR` 是 URL 参数，会被静默忽略** —— 实测同一检索词返回 48144 条 `source=MED` 的正式论文（带真 PMID），而不是预印本。正确写法是把 `SRC:PPR` 写进检索式 | ✅ 已修（实测 573 条纯预印本） |
| P2 | stats-dev | **bioRxiv 旧 URL 形式 `/details/{server}/{start}/{count}` 已失效**，返回 HTTP 200 + 空 collection，看起来像"检索到 0 篇"。现行形式是 `/details/{server}/{YYYY-MM-DD}/{YYYY-MM-DD}/{cursor}` | ✅ 已修，并显式检查 `messages[0].status`——上游 200 但 status≠ok 现在会写进 `error` |
| P3 | stats-dev | **bioRxiv 作者串是分号分隔**（`"Harvey, D. Y.; Stoll, H."`），按逗号切会得到 `['Harvey','D. Y.','Stoll','H.']` | ✅ 已修，转成 PubMed 风格的 `"Harvey DY"` |
| P4 | export-dev | **PubMed 的作者格式是 `"Harvey DY"`、预印本是 `"Harvey D Y"`** —— 同一文献两版会导致 BibTeX 引用键不一致甚至撞键 | ✅ 已修 |
| P5 | export-dev / stats-dev | **预印本进了候选池却无法被正文引用**（它们没有 PMID，`[PMID:xxx]` 引用不到）——等于白检 | ✅ 已修：预印本用 `[DOI:xxx]` 引用，引用校验同时查两个池子 |
| P6 | 我自己 | **预印本在 BibTeX/RIS 里没有标记**，读者会误以为是正式论文 | ✅ 已修：BibTeX 用 `eprint`+`archivePrefix`+`note={Preprint}`，RIS 加 `N1  - Preprint`；GRADE 定级对预印本降级 |
| P7 | stats-dev | 预印本的年份用 `pubYear`，部分平台（如 Research Square）不准 | ⏳ **仍未修**：应改用 `firstPublicationDate` |
| P8 | stats-dev | 只扫"最新一批"预印本召回极差（实测某主题最新 240 条命中 0 篇） | ✅ 已修：改成"一半取最新保时效、一半在窗口内分层保覆盖" |

> **方法学备注**：stats-dev 对自己的修复做了**变异测试**（把每个修复逐个退回成 5 个变异体），
> 确认都有用例能抓到。其中 2 个变异体最初**存活**了——说明当时的用例不具区分度，已改写。
> 这种"验证测试本身有效"的做法值得保留。

## 四、我这边的判断

第一轮改完，**架构层面已经没有明显短板了**：检索有质量闸门和三种补漏机制，
证据有机械定级、撤稿拦截、偏倚要素、效应量合并，输出有 PRISMA/GRADE/多格式导出，
工程有单测/CI/断点续跑。

**剩下的短板集中在两处：**
1. **语料覆盖**（N1 中文文献、N6 语种）——这是"值不值得被用起来"的关键，
   也最可能成为你提个性化意见的重心。
2. **交互形态**（N5 横向对比、N4 结构自检）——决定它是一次性查询工具，
   还是能进日常工作流的研究助手。

**我的建议**：先跑 2–3 个你真实课题的问题，看看输出里哪部分最碍事，
再据此排第二批——**你提的个性化意见大概率比我现在列的这些更准**。
