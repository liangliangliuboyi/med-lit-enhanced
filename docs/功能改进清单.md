### NCBI 恢复后的实测发现（2026-11-05 晚）

> ⚠️ **本节 Q1 的结论已被 2026-11-05 深夜的第三轮审查推翻并更正**，请以 Q1' 为准。
> 原结论把"命中数下降"当成了"有效降噪"，实际上那次测的是**一个语义写反的过滤器**。

| # | 发现 | 证据 | 处理 |
|---|---|---|---|
| **Q1'** | **动物排除过滤器的语义是反的** —— 写法 `NOT ("Animals"[MeSH] NOT "Humans"[MeSH])` 会被 PubMed **丢弃外层 NOT**，实际执行成 `AND ("Animals" NOT "Humans")`，即"只要动物、不要人类"。结果是把**所有人体研究滤掉、只留纯动物研究** | 同一个检索式（`"Glucagon-Like Peptide-1 Receptor"[MeSH] AND ("Obesity"[MeSH:explode] OR "Overweight"[MeSH]) AND (weight loss[tiab] OR body weight[tiab] OR body mass index[tiab])`）实测：<br>· 裸检索式 **473**<br>· 错误写法 `AND NOT (Animals NOT Humans)` → **102**（掉了 95.6%）<br>· 正确写法 `AND NOT (Animals AND NOT Humans)` → **371**（只掉 21%）<br>· 错误写法下，那篇纯小鼠研究（PMID 38218536）**仍在结果里** | ✅ **已修**：改为 `NOT ("Animals"[MeSH] AND NOT "Humans"[MeSH])`。修复后 371 命中、纯小鼠文献被正确排除。`pubmed.py` 里写清了两种写法的实测差异，防止再改错 |
| **Q2** | `'Antibodies, Monoclonal, Humanized'` 这类含 "Human" 的词**不是** `Humans` 标记 | MeSH 词表里 Humans 是独立树节点 | 精确匹配 `humans` / `humans ` 前缀，不做子串匹配。已补 5 个用例（含"人+鼠混合的转化医学研究要保留"） |

> **这条的意义**：**"过滤后命中变少"不等于"过滤正确"** —— 必须验证被保留下来的到底是不是想要的东西。
> 错误过滤器最危险的地方在于：它**不报错、还很有说服力**（命中数下降了嘛），
> 只是把方向搞反了，人体研究被当成动物研究丢掉。
> 本项目因此确立一条原则：**检索式交给检索侧、最终把关交给程序侧**
> （`is_animal_only()` 按 efetch 回来的 MeSH 再判一次）。
> 同类需要程序侧兜底的地方还有：撤稿检查、文献类型、摘要长度。


| # | 来源 | 问题 | 状态 |
|---|---|---|---|
| P1 | stats-dev | **Europe PMC 的 `source=PPR` 是 URL 参数，会被静默忽略** —— 实测同一检索词返回 48144 条 `source=MED` 的正式论文（带真 PMID），而不是预印本。正确写法是把 `SRC:PPR` 写进检索式 | ✅ 已修（实测 573 条纯预印本） |

### 4.6 模型对长文本的处理能力差异巨大（实测）

**同一篇 26000 字全文的 reader prompt**：

| 模型 | 耗时 | 结果 |
|---|---|---|
| `deepseek-ai/DeepSeek-V3.2` | **13.1s** | ✅ 正常返回（6456 tokens） |
| `Qwen/Qwen3.5-35B-A3B` | **180.1s** | ❌ 请求超时 |

**同一份相关度打分 prompt（短输入）**：

| 模型 | 耗时 | 结论 |
|---|---|---|
| `Qwen/Qwen2.5-7B-Instruct` | **0.7s** | ✅ 最快 |
| `Qwen/Qwen3-14B` | **1.5s** | ✅ |
| `deepseek-ai/DeepSeek-V3.2` | **2.5s** | ✅ |
| `Qwen/Qwen3.5-35B-A3B` | **53.2s** | ⚠️ 慢 |
| `Qwen/Qwen3.5-27B` | **57.2s** | ⚠️ 慢 |
| `Qwen/Qwen3.5-9B` | **60.1s** | ❌ 直接超时 |

> 两个结论：
> ① **"模型能处理长文本"不是理所当然的** —— 同一份 prompt，有的 13 秒，有的根本跑不完。
> ② **Qwen3.5 系列整体偏慢，Qwen3 / Qwen2.5 系列偏快** —— 链的顺序要按实测速度排，
>    否则首选模型一失败，降级链就会撞上慢模型。
>
> 据此已做：交叉验证的第二模型改从 **`fast` 链**取（轻量判断任务用小模型即可，
> 原来取 reader 链第 3 位，5 篇串行实测 **458.8 秒**）；`config.example.json`
> 的默认链按实测速度重排，并把会直接超时的 `Qwen/Qwen3.5-9B` 从 fast 链首位挪走。

### 4.7 超时相关的四层保险（已实现）

```
一次 chat 调用
  ├── 单次请求超时  reader_timeout（90s，通用角色 180s）
  │     └── socket 超时 → 不重试（直接换模型）
  ├── 失败计数      连续失败 N 次（默认 2）才降级
  │     └── 偶发失败不再"永久拉黑"首选模型、污染整个角色
  ├── 降级链        链上多个模型依次尝试
  └── 总时长预算    model_call_budget（240s）→ 耗尽即停
```

四道保险的作用分别是：**别在坏请求上浪费时间**、**别让一次偶发失败拖垮整轮**、
**换个能用的模型**、**别让整轮拖死**。

> **这一整条是踩出来的，不是设计出来的**：2026-11-05 的真实运行卡了 28 分钟，
> 进程 CPU 几乎为 0（纯网络等待）。查下来是"超时 × 重试 × 降级链 × 全局拉黑"四层叠加。
> **教训：任何"重试 + 降级"机制，都必须有一个总时长上限和"别把偶发失败当永久失败"的机制。**

### 4.9 这一轮又抓到的三个真问题

## 五、我这边的判断

两批改进全部实现后，**架构层面已经没有明显短板了**：

- **检索**：质量闸门 + 三种补漏机制（链接扩展／滚雪球／预印本）+ MeSH 树 + 年份自适应 + 语种限制 + 缓存
- **证据**：机械 GRADE + 撤稿拦截 + 偏倚要素 + 效应量合并 + PICO 匹配度 + **语义比对** + **双模型交叉验证**
- **输出**：PRISMA + GRADE + 覆盖说明 + 适用边界 + 结构自检 + 四种导出 + 横向对比
- **工程**：单测 + CI + 断点续跑 + 分档计价 + 全中文报错

**剩下的短板只有一处，而且它不是技术问题**：
**中文文献覆盖**。这个工具目前只检索 PubMed 与预印本服务器（国际英文文献）。
对上海交大医学生的真实需求来说，中文指南、中文共识、中文期刊系统评价是**够不着**的部分。
这不是加个 API 能解决的——需要 CNKI／万方／维普的**可用授权**。
在那之前，工具会在答案里明确写「本轮检索未覆盖中文文献」，不糊过去。

**接下来的建议**：
1. 等 NCBI 恢复后，用你**真实的课题问题**跑 2–3 次（这一步比再写代码更有价值）；
2. 看输出里哪部分最碍事——是检索式、证据表、还是结论措辞；
3. 你的个性化意见大概率比我列的这些更准。

| 写法 | PubMed 给的 | JCR 表给的 |
|---|---|---|
| NEJM | `N Engl J Med` | `NEW ENGLAND JOURNAL OF MEDICINE` |
| JAMA | `JAMA` | `JAMA-JOURNAL OF THE AMERICAN MEDICAL ASSOCIATION` |
| 刊名里有冠词 | `The Journal of clinical investigation` | `JOURNAL OF CLINICAL INVESTIGATION` |

刊名匹配只能靠模糊，命中率不可靠；ISSN 是唯一稳定的连接键。
匹配顺序：**ISSN → 规范化刊名 → 缩写刊名 → 主刊名 → 前缀（唯一才用）→ 模糊（阈值 0.86）**。

**实测**：真实 PubMed 题录 59 篇样本 → **命中 54 篇（91%）**，全部走 ISSN（O(1) 字典查找）。
未命中的 5 篇是俄语小刊与 CME 刊，确实不在 JCR 索引里。

**三个必须做对的细节**（都踩过）：

| 坑 | 后果 |
|---|---|
| 只规范化查询值不规范化映射表的键 | ISSN 永远对不上（查询去连字符、键还带连字符） |
| 不剥刊名开头的冠词 | PubMed 的 `The Journal of…` 与 JCR 的 `JOURNAL OF…` 差一个 `the `，精确匹配必然落空 |
| 不建「主刊名」索引 | `JAMA`/`BMJ` 这类短刊名查不到（JCR 把主刊名与副标题用 `-` 连在一起） |

**两条体系必须分开**：**JCR 分位（Q1–Q4）与中科院大区（1–4）是两套东西**，
混在一列是国内学术评价里最常见的误读来源。索引里各占一个字段，
展示时也是 `IF 109 · JCR Q1 · 中科院 1 区`。

**还加了一条纪律**：writer 提示词里明确写「IF/分区只用来向读者说明**来源量级**，
**不得**用它来质疑或抬升证据本身」。不分发这个字段之前，模型很容易犯
"高分区期刊 = 高质量证据"的错。

#### ② 全文获取层（原来只有 PMC BioC 一条路）

**问题**：`pubmed.fulltext()` 只会抓 PMC 的开放全文。绝大多数临床文献不在 PMC，
用户拿到的其实是**摘要**——而摘要会省略关键结局。

**做法**：新增 `scripts/fulltext.py`，降级链
**PMC BioC → Europe PMC → PMC HTML → Unpaywall → OpenAlex**。

**实测出来的降级链不是拍脑袋定的**。对 PMC12439189（JAMA Pediatrics 2025）：

| 来源 | 结果 |
|---|---|
| PMC BioC | HTTP 200 但内容是**错误页**（"[Error] : No result can be found."） |
| Europe PMC XML | HTTP 500（fullTextXML）/ 404（MED 形式） |
| Unpaywall | 只找到**补充材料** PDF（`.../bin/xxx-s001.pdf`），不是正文 |
| **PMC HTML** | **HTTP 200，233KB** ✅ 正文 32,067 字 + 6 个章节 + 4 张带图注的插图 |

而 **PMC HTML 是唯一能给图片直链的免费全文源**
（`https://cdn.ncbi.nlm.nih.gov/pmc/blobs/.../xxx-g002.jpg`）——
图表识别模块就靠它把森林图喂给多模态模型。这一级不加，
「图表识别」对 PMC 文章根本无从下手。

**还踩到一个反爬坑**：PMC 的 reCAPTCHA 挑战页是**随机命中**的——
同一个 URL 连抓 8 次，新域名 6 次中招、老域名 2 次中招，
挑战页只有 21KB 的 Google JS，和正文毫无关系。
解法是**两个域名依次试 + 每域名最多 2 轮、间隔 1.5 秒**，
单轮成功率约 70%，两轮约 90–100%。另加正文长度门槛（≥200 字），
挡住"容器在但正文没渲染出来"的空壳页。

两个关键设计：

- **下载与"不落地读取"分开**。`fetch()` 会把 OA 论文的 PDF 存到
  `07_fulltext_pdf/`；`fetch_ephemeral()` 只在临时目录读，**读完立刻删除并确认删除成功**
  （用户说"我不想留文件"时用 `--no-download`）。
- **拿不到就给可执行的指引**，而不是默默用摘要凑合。
  `acquisition_guide()` 逐条给出题名、DOI、PubMed/PMC 链接，
  并提醒「若提示付费墙或连接失败，请开启 网络代理 / 交大医学院 VPN，
  或通过交大图书馆校外访问入口获取」。这段会写进 `06b_fulltext_guide.md`，
  **也会喂给 writer**，于是答案里自动多出一节"哪些只读了全文、去哪儿拿"。

**代理探测**：环境变量优先，其次 Windows 注册表 `Internet Settings\ProxyServer`。
实测本机环境变量里有代理、出版商站点 ScienceDirect/Wiley 返回 403
（出版商挡爬虫）——**这正是需要引导用户走机构 VPN 的原因**。

#### ③ 图表识别（原来完全没有）

**问题**：循证医学里最关键的信息常常**只存在于图里**——
森林图上的 HR/OR/RR 与 95%CI、生存曲线、ROC 曲线。只读摘要会整片漏掉。

**做法**：新增 `scripts/figures.py`，用多模态模型
（默认 `Qwen/Qwen3-VL-8B-Instruct`，可换 `Qwen/Qwen3-VL-30B-A3B-Instruct`）
读论文插图。

四条硬性设计：

1. **图片 base64 内联**（不用远程 URL）——出版商与 PMC 的图床常有防盗链与超时。
2. **并发度默认 4、硬上限 8**，每张图单独短超时。
   理由是本仓库吃过的两次亏：「并发打长文本会超时」。
3. **返回顺序按 index 还原**——并发下完成顺序是乱的，直接 append 会让顺序乱掉。
4. **提示词要求"只抄图上真实出现的数值，读不清就写『图中未见明确标注』"**。
   循证场景里编造效应量是严重错误，所以这条写进了提示词，也写进了测试。

结果进证据表的「图表要点」列，完整内容另存 `05c_figures.md`。

**必须说清的分辨率限制**：PMC 归档的插图分辨率通常只有出版社原图的**一半**
（实测 690×1310 vs 1381×2621）。在一张 **227 行**的密集森林图上，
模型把 **−0.227 读成了 −0.219**。

**这两条 PMC 路径给的是同一张图**（实测 PMC4580597 的 g002：
CDN 直链 690×1310 / 254KB，Europe PMC 打包 zip 里也是 690×1310 / 254KB）。
所以**打包 zip 不是高分辨率来源**，别指望换条路就能拿到出版社原图——
那需要出版商特定的 URL 拼法（PLOS 的 `?size=large&id={doi}.gNNN`），
通用不了。

**结论：分辨率问题在 PMC 范围内无解**，只能靠两条纪律兜住：
① 提示词里区分两种森林图，且低分辨率读不清时**老实输出「图中未见明确标注」**，
   宁可少报也不编（这是硬底线）；
② 输出文件与 writer 提示词里都写明「行数很多的森林图，其数值只能当参考，
   关键数字请回原图核对」。

所以：
- 提示词里区分两种森林图：**有汇总行**（标着 Combined effect size / Overall）
  只报汇总行；**没有汇总行**（每行一个结局，十来行）才逐行列出。
- 输出文件与 writer 提示词里都加了分辨率提示，
  要求引用图表数值时用「图示」措辞，行数多时提示读者回原图核对。

**提示词的一个真 bug（靠实跑夹具抓到的）**：
最初提示词只写了「森林图：只报**汇总那一行**」——那是给「227 行研究 + 一个
合并效应量菱形」的经典森林图设计的。但**结局维度的森林图每一行都是不同的结局指标、
根本没有汇总行**，按「只报汇总行」读就会漏掉一大半：
实测 JAMA Pediatrics 那张 9 个结局的森林图**只读出 5 个**（丢了 HbA1c、
空腹血糖、BMI 百分位、舒张压 4 个）。
修法：把森林图拆成两个分支，并各给一个**具体写法示例**（示例是模型照抄格式的依据，
实测很关键）：

```
(a) 有汇总行（Combined effect size / 合并效应量 / 合计 / Overall / Random effects，
    通常配一个菱形）：只报这一行的效应量与 95%CI + 纳入研究数 k。
(b) 没有汇总行（每行都是不同的结局/指标/亚组，行数不多）：
    每一行都列出来，格式「行标签：效应量 (95% CI 下限到上限)」，
    行标签照抄图上原文，不要自己翻译。
```

修完后独立复测：**9/9 结局全部读出，数值与标签逐字一致**，
流程图也读出 468→334→58→18 的 PRISMA 计数，12 秒 2 张图。

**模型选型实测**（同样的图，不同模型）：
- `Qwen3-VL-8B-Instruct`：单张 9 秒 / 764 token，读出 9 个结局的 ETD 与 95%CI ✅
- `Qwen3-VL-30B-A3B-Instruct`：22 秒 / 1435 token，质量相当但慢一倍多
- `Qwen3-VL-32B-Thinking`：56 秒，会先输出大段推理
- `Qwen3-Omni-30B-A3B-Instruct`：**不适合图任务**——它是音视频多模态，
  图像分支能力弱，还把森林图误判成流程图
→ 默认用 `Qwen3-VL-8B-Instruct`，`30B-A3B` 作为升级选项。

#### ④ 连续提问：证据池复用（原来每轮从零重读）

**问题**：用户的真实用法是"围绕一个课题反复追问"。
原实现每轮都重新检索 + **重新精读全部文献**——同一篇重读一次是一次完整的模型调用，
而抽取结果几乎必然一样。

**做法**：`Run` 增加 `prior_evidence`，追问时沿用上一轮已精读过的文献
（证据表标 `↺沿用`）。成本从「检索 + 全量精读 + 审稿 + 成文」
降到「检索 + 只精读新文献 + 审稿 + 成文」。

**代价要说清楚**：reader 的抽取是**相对上一个问题**做的，
所以复用来的 `key_findings` 带着上一轮问题的视角。
缓解办法：复用项打 `_reused` 标记，writer 拿到的是完整证据表 + 新问题，
会据此重新作答。这条权衡已写进代码注释。

### 5.3 顺手修掉的一个真 bug

**`--chat` 模式下所有命令行开关都失效**。原因是「参数覆盖配置」那段代码
排在 `--chat` 分支的 `return` **之后**——于是 `--quick`、`--max-papers`、
`--fulltext-limit` 在聊天模式下统统不起作用。
已把这段抽成 `_apply_overrides(cfg, args)` 并提到 `--chat` 分支之前。

### 5.5 仍然存在的短板（如实记录）

1. **PDF 文本抽取已解决**（`scripts/pdftext.py`，纯标准库）：
   扫 obj 定位对象（不解析 xref 表——真实 PDF 的 xref 常是增量更新的）、
   ToUnicode CMap 解析（bfchar / bfrange，这是能不能读懂中文 PDF 的分水岭）、
   **质量闸门**（控制字符 > 2% 或词形字符 < 50% 判为乱码，拒绝采用——
   宁可没有正文，也不要把乱码喂给模型污染证据抽取）。
   顺带还能从 PDF 里抠出内嵌图片（JPEG 直出 + 纯 stdlib PNG 编码）。
2. **中文文献完全未覆盖**——这是用户明确决定的，不是缺陷。
   答案里会明写「本轮检索未覆盖（仅检索了国际英文文献）」，不糊过去。
3. **只有 PubMed 一个库**——预印本（bioRxiv/medRxiv）已接，
   但 CNKI / 万方 / 维普需要机构授权，不是加个 API 能解决的。
4. **JCR 数据是 2026 版快照**——明年需要重跑 `build_jcr_index.py` 更新。

### 5.6 这一轮自己踩的三个坑（都是实测出来的，不是推演）

| # | 坑 | 后果 | 修法 |
|---|---|---|---|
| **S1** | **重排接口只返回 top_n 条**，多样性平衡看到的"完整列表"其实只有 5 篇 | 候选池里明明有 3 篇 NEJM 的 RCT，却因 top_n=5 全被挡在证据池外，证据池最后全是系统综述 | 重排多取几条（`max(limit*4, limit+5)`），再从中做多样性选择。**多返回结果不额外花钱**（同样的打分，只是多返回） |
| **S2** | **图表识别的 `key_values` 模型返回的是数组**，代码用 `str()` 转 | 变成 Python 字面量 `"['Glycated hemoglobin...', ...]"`，而这个字符串会**原样塞进证据表与答案** | 加 `_as_text()` 统一归一化：数组用「；」连接、空数组 → 空串（不能变成 `'[]'`）、字典 → 空串 |
| **S3** | **`git add -A` 在子代理还在写文件时跑** | 把子代理**写到一半的中间态**提交进了 git 历史（正则 group 名 `dict_open` 与代码里的 `dictopen` 不一致 → 所有对象的字典都是空的 → 一个页面都识别不出来），而且我随后测的是**历史版本**，误以为是修好的 | 子代理还在写时不要 `git add -A`；测**工作区**的当前文件而不是 git 里的版本 |

**还有一个"看起来对但其实没生效"的**（S1 就是）：证据池多样性平衡的代码写好了、测试也全绿，
但**在真实运行里从来没触发过**——因为它依赖的输入被上游截断了。
**测试全绿 ≠ 功能生效**，必须跑一次真实查询看日志。
